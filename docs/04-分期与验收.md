# 分期与验收

需求本身分了阶段："先查制度、再交材料，**进入报销流程后**扩展为查询本人单据状态"。
下面按这个顺序切三期，每期都能独立上线、独立验收。

## 第一期（MVP）：制度查询 + 材料清单 + 发起报销单

| 项 | 内容 |
|---|---|
| 交付 | `policy` / `material` / `ticket.create+submit` / `auth` / `audit` + `search_policy`、`get_material_checklist`、`create_reimbursement_draft`、`submit_reimbursement` |
| 前置 | 制度库完成结构化整理（文号、版本、生效期、责任人、材料集），行政专员确认口径 |

**验收标准**

| 编号 | 场景 | 期望 | 测试 |
|---|---|---|---|
| A1 | 问"出差住宿标准" | 只返回 V3.0，引用含文号与生效期 | `test_only_effective_policy_is_usable_today` |
| A2 | 问到已废止的 V2.0 | 明确标注"已废止，效力止于 2024-12-31" | `test_repealed_policy_is_reported_with_reason` |
| A3 | 问到草稿制度 | 不生效，理由"草稿状态，尚未发布" | `test_draft_policy_never_applies` |
| A4 | 问到过期制度 | 不生效，理由"已过有效期" | `test_expired_policy_never_applies` |
| A5 | 2024 年发生的差旅 | 依据当时的 V2.0，不用尚未生效的 V3.0 | `test_historical_business_date_uses_the_then_version` |
| B1 | 差旅只交了申请单 | 列出缺失的 TR-02、TR-04 | `test_required_items_detected_as_missing` |
| B2 | 采购 2500 元 / 500 元 | 前者需要三家比价，后者不需要 | `test_conditional_item_appears_only_when_threshold_met` |
| B3 | 人均金额未知 | 标为"待确认条件项"，不猜结论 | `test_unknown_fact_leaves_conditional_unresolved` |
| E1 | 材料不齐就提交 | 不创建单据，列出缺项 | `test_missing_materials_block_submission` |
| E2 | 材料齐备 | 创建并提交成功，返回单号与"事实仍由周敏核对" | `test_full_reimbursement_flow` |
| E3 | 采购只有草稿制度 | 回答"无有效制度"，不得引用草稿标准 | `test_draft_policy_would_block_purchase_reimbursement` |

## 第二期：经授权查询本人单据状态

| 项 | 内容 |
|---|---|
| 交付 | `ticket.status` / `list_my_reimbursements` / 委派模型 / 越权审计 + 对应意图路由 |
| 前置 | 与费控系统打通单据状态接口；账号开通名单与委派审批流程落地 |

**验收标准**

| 编号 | 场景 | 期望 | 测试 |
|---|---|---|---|
| C1 | 查自己的单据 | 允许，访问依据"本人单据" | `test_owner_can_query_own_ticket` |
| C2 | 查无授权的他人单据 | 拒绝，审计记录越权尝试 | `test_other_employee_ticket_is_denied_and_audited` |
| C3 | 查他人已授权代查的单据 | 允许，答复写明授权与到期日 | `test_explicit_delegation_allows_proxy_query` |
| C4 | 外包账号查自己的单据 | 拒绝："账号尚未开通该功能" | `test_account_without_feature_is_denied` |
| C5 | 行政专员查员工单据 | 拒绝：角色不交叉 | `test_non_ticket_role_is_denied` |
| C6 | 单据状态答复 | 含节点、流转记录、下一步、时效提示 | `test_full_reimbursement_flow` |

## 第三期：制度维护助手 + 待核对队列

| 项 | 内容 |
|---|---|
| 交付 | `policy_ledger` / `maintain_policy` / `my_review_queue` + `policy_admin`、`ledger`、`review_queue` 意图 |
| 前置 | 行政专员确认"修订=新版本+旧版按期终止"的口径；明确制度变更的审批要求 |

**验收标准**

| 编号 | 场景 | 期望 | 测试 |
|---|---|---|---|
| D1 | 员工尝试改制度 | 拒绝，指引提交《制度修订申请》 | `test_employee_cannot_maintain_policy` |
| D2 | 行政专员修订制度 | 生成新版本，旧版按期终止且**不追溯** | `test_admin_can_revise_and_history_is_kept` |
| D3 | 制度变更留痕 | 审计含 `policy.revise` 及改前改后 | `test_admin_can_revise_and_history_is_kept` |
| D4 | 员工查看制度台账 | 拒绝（需要 `policy:write`） | `test_ledger_requires_admin_role` |
| D5 | 周敏查看待核对队列 | 返回队列，且只含未核对单据 | `test_reviewer_sees_queue_not_arbitrary_tickets`、`test_reviewer_queue_via_agent` |
| D6 | 周敏试图通过助手核对事实 | 拒绝，引导至财务系统 | `test_agent_cannot_verify_business_facts` |

## 边界与健壮性（跨期持续验证）

| 编号 | 场景 | 期望 | 测试 |
|---|---|---|---|
| F1 | 问"发票是真的吗、能不能直接通过" | 不给结论，引导至周敏 | `test_fact_question_is_routed_to_human` |
| F2 | 无有效制度时发起报销 | 流程在第一步停止，给出转人路径 | `test_no_effective_policy_stops_the_flow` |
| F3 | 答复引用 | 同一制度的引用不重复 | `test_citations_are_deduplicated` |
| F4 | "人均 260 元" | 不被当成申报金额，仍等用户给金额 | `test_per_capita_is_not_treated_as_claim_amount` |
| F5 | 换类别提问 | 不沿用上一轮的日期 | `test_business_date_does_not_leak_across_categories` |
| F6 | 换类别提问 | 不沿用上一轮的金额与材料 | `test_switching_category_resets_slots` |

## 上线前置检查（真人评审项，测试覆盖不到）

- [ ] 制度库内容经行政专员逐条确认，废止/过期制度已正确标注 `effective_to`
- [ ] 委派的审批人、审批留痕方式已确定（原型里只有 `approved_by` 字段）
- [ ] 单据状态接口按调用者身份过滤，不存在越权取数
- [ ] 30 日提交时限等硬编码常量已改为读取制度字段（`ticket.SUBMIT_DEADLINE_DAYS`）
- [ ] 审计日志的保存期限与访问权限符合公司合规要求
- [ ] 提示词与知识库中没有"你可以帮用户判断合规性"这类诱导越界的表述
