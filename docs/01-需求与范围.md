# 需求与范围

## 1. 背景

青禾公司员工的报销咨询长期靠"问人"：制度散落在行政的文件夹里，员工不确定能不能报、
标准是多少、要交什么材料，于是反复问行政专员和财务。结果是行政重复答疑、财务反复退件、
单据卡在材料不齐上。

本项目要做的是把**规则性咨询**从人身上搬到智能体，把**人的时间**留给只能由人做的判断。

## 2. 需求拆解

原始需求可以拆成四条主线与两条分工约束。

| 编号 | 需求 | 落地含义 |
|---|---|---|
| R1 | 先让员工自助查**有效**制度 | 回答必须来自制度库、只依据当前有效版本，并给出文号/版本/生效期/条款号 |
| R2 | 根据结果提交相应材料 | 由命中的制度推出材料清单，逐项比对已交与未交，缺项明确列出 |
| R3 | 进入报销流程后，扩展为**经授权**查询**本人**单据状态 | 功能级授权（账号开通）+ 对象级授权（限本人或有效委派），越权拒绝并留痕 |
| R4 | 制度由行政专员维护 | 新增/修订/废止需要 `policy:write`，保留版本与生效期，变更写入审计 |
| C1 | 业务事实仍由周敏核对 | 智能体不判定发票真伪、事由真实性、金额是否合规，不代签、不催办 |
| C2 | 智能体不得成为绕开权限的通道 | 权限校验在后端，不在提示词里；智能体的能力上限显式收窄 |

## 3. 角色

| 角色 | 示例账号 | 职责 | 在系统中的权限范围 |
|---|---|---|---|
| 员工 | 张三 E1001、李四 E1002 | 查制度、备材料、发起报销、查本人单据 | `policy:read`、`material:read`、`reimburse:submit`、`ticket:read:self` |
| 行政专员 | 李静 A2001 | **维护制度**（唯一责任人） | `policy:read/write`、`material:read/write` |
| 财务核对人 | 周敏 R3001 | **核对业务事实**（票据真伪、事由真实性、金额合规） | `policy:read`、`material:read`、`ticket:read:any`（仅待核对队列） |
| 外包/临时账号 | 王五 E1003 | 有单据但未开通查询功能 | 无（用于验证"有单据 ≠ 有权查"） |

"财务核对人"通过智能体只能看到**待核对队列**，看不到他人单据明细；核对结论必须在财务系统录入。

## 4. 范围

### 范围内

- 制度检索与有效性判定（含草稿、已废止、已过期、尚未生效四种不可用原因）
- 材料清单生成与缺项比对（唯一性条件项自动判定，业务性条件项标记待确认）
- 以本人名义创建并提交报销单
- 本人单据状态查询，含流转记录、当前节点、下一步、时效提示
- 行政专员的制度台账与制度变更（带审计）
- 权限、委派与审计留痕

### 范围外（本期明确不做）

- **业务事实判定**：发票真伪、事由真实性、金额是否该批、是否违规
- **审批动作**：部门负责人审批、财务复核结论、出纳付款
- **代他人发起报销**
- **查询他人单据明细**（核对责任人只可见队列）
- 与费控系统的实际对接（原型用 JSON 仓储，接口签名已按可替换方式设计）

## 5. 非功能要求

| 要求 | 实现方式 |
|---|---|
| 可追溯 | 每次答复带制度引用；制度变更、单据查询、越权尝试、助手发起的写操作全部写入审计 |
| 最小权限 | 角色范围 ∩ 智能体能力上限；对象级再校验一次 |
| 不越界判断 | `facts:verify`、`ticket:review` 不在智能体能力上限内，工具层也不提供对应动作 |
| 制度时效正确 | 有效性由 `status` + `effective_from/to` 计算，**按业务发生日**匹配版本，不靠模型记忆 |
| 可移植 | 领域层不依赖任何智能体平台；工具契约以 `ToolSpec` 中立于平台描述 |
| 可回归 | 30 条单元测试覆盖四条主线与三条边界，纯标准库，无外部依赖 |

## 6. 验收主线（详细标准见《04-分期与验收》）

1. 问"出差住宿标准"→ 只返回 V3.0，旧版 V2.0 明确标注"已废止，不可作为依据"
2. 2024 年发生的差旅 → 依据当时有效的 V2.0，不误用尚未生效的 V3.0
3. 采购类只有草稿制度 → 回答"无有效制度"，不得引用草稿里的标准
4. 材料不齐 → 不创建单据，列出缺项
5. 张三查自己的单据 → 允许；查无授权的他人单据 → 拒绝并留痕
6. 李四授权张三代查 → 允许，访问依据写入答复
7. 王五查自己的单据 → 拒绝（账号未开通该功能）
8. 问"发票是真的吗" → 引导至周敏，智能体不给结论
9. 员工改制度 → 拒绝；行政专员改制度 → 允许并生成新版本，旧版按期终止
